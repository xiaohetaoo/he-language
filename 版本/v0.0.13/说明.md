# 核语言 0.0.13

一门用中文写程序的语言，语法与 Python 相似。源文件后缀 **`.xht`**。

第一版不引入任何第三方库：一个命令行解释器 + 一个 PyCharm 风格的图形界面。

```
核说（"你好，世界！"）
```

### 代码折叠

以冒号结尾、且下一行缩进更深的行，行号左侧会出现一个 `▼`。
点它就折起来（变成 `▶`），再点展开：

```
▼ 核定义 算总分(成绩单)：
▶ 核说("算完了")
```

- 鼠标移到 `▼` 上会变亮，光标也会变成手型
- `核核` 行尾注释不影响判定，`核若 x： 核核 说明` 照样能折
- 回车自动缩进用**同一套**「块开头」判定，所以带行尾注释的冒号行回车后
  也会缩进一级（以前两处口径不一致：能折叠却不缩进）
- 光标**不会**停在被折起来的行上：万一落进去（查找定位、撤销），
  那一块会自动展开，避免在看不见的地方改到代码
- 折叠位置跟着代码走 —— 在函数上面插几行，折叠不会跑到别的函数上去
- 折叠范围做了缓存，只有被改动的那一段会重算：2000 行文件下重算
  从 4.6ms 降到 2.4ms，8000 行从 18.7ms 降到 7.1ms

### 版本控制（只读）

顶行会显示当前分支和改动数，例如 `⎇ main  ✚3`，点开是改动文件清单，
双击一行可在编辑器里打开该文件。

> **只做展示，不做提交与推送。** 推送需要事先确认，把按钮做进界面
> 等于给了一条绕过确认的快捷路径。要提交/推送，请在命令行或
> git 客户端里进行。
>
> 没装 git、或项目目录不在仓库里时，这里显示「未启用」，不影响其他功能。

读状态要串行跑 4 个 git 子进程（`--is-inside-work-tree`、`rev-parse`、
`status --porcelain`、`rev-list`），每个超时上限 6 秒。这件事在**后台线程**
里做，结果用信号回填到按钮 —— 所以按 `Ctrl+S` 不会卡界面。
同一时刻只允许一个查询在跑，飞行期间的请求合并成一次补跑，
连点保存不会堆出一串并发子进程。

## 二、语言规则

### 2.1 中英文符号视同

代码区的全角符号自动当半角用，**字符串和注释里的内容原样保留**：

```
核说（"你好，世界！"）       核核 括号、引号、逗号都是全角 → 能跑
核说（"你好，世界！"）       核核 引号里的「，」「！」不会被改动
核说（「引号也认」）          核核 “ ” ‘ ’ 「 」 『 』 都当引号
```

归一范围：`， ： ； （ ） ［ ］ ｛ ｝ " ' = + - * / % < > & | ^ ~ @ # $ \ _ 　`，
以及全角数字与字母（`１２３`、`ａｂｃ`）。

**中文引号左右各自配对**（0.0.13 起）：

| 开头 | 只能由 | 收尾 |
| --- | --- | --- |
| `“` | | `”` |
| `「` | | `」` |
| `『` | | `』` |
| `‘` | | `’` |
| `"` | | `"` |
| `'` | | `'` |

也就是说，中文引号里再套一层是完全合法的：

```
核说（“成绩里没有「数学」这一项”）     核核 整句都是字符串
核说（“外层『内层』结束”）
```

以前 `“”「」『』` 六个字符共用一个收尾集，于是上面第一句里内层的 `」`
会被当成外层 `“` 的收尾符，字符串从中间断开，产物编译不过。
只写了右引号当开头（`”…`）的情形仍然放宽，因为那多半是「只打了一边」的手误。

`「…」` 里若出现 ASCII 引号（`核说（「他说"你好"」）`），转译时会自动加上反斜杠，
保证产物是合法 Python；运行时拿到的字符一个没变。

### 2.3 英文写法照样能跑

规则表里的中英文**都认**：`print` 与 `核说` 等价，`if` 与 `核若` 等价。
`len`、`sorted`、`upper`、`end` 这些出现在对照表右列的英文，同样视为「已定义」。

### 2.4 未定义清单：未定义的写法原样保留

源码里出现、但对照表没定义的**英文**写法，会原样交给 Python 执行，
同时记进当前目录的 **`未定义.txt`**：

```
# 核语言 未定义清单
# 说明：下面这些写法出现在源码里，但核语言对照表还没有定义，
#       已按原样交给 Python 执行。把它们补进对照表，就能用中文写。
# 格式：写法 <TAB> 类别 <TAB> 出现次数 <TAB> 首次位置 <TAB> 最近位置

sum	内置函数	2	例子/05_未定义演示.xht:3:4	例子/05_未定义演示.xht:3:4
type	内置函数	1	例子/05_未定义演示.xht:9:4	例子/05_未定义演示.xht:9:4
capitalize	方法	1	例子/05_未定义演示.xht:6:9	例子/05_未定义演示.xht:6:9
file	参数名	1	例子/05_未定义演示.xht:12:11	例子/05_未定义演示.xht:12:11
```

- **跨运行累积、按「写法 + 类别」去重**，次数累加，位置取首次与最近。
- 位置是相对清单文件的路径，方便直接定位。
- 用户自己定义的名字（`核定义`、赋值左边）不会被误报。
- 清单默认写在**当前工作目录**（图形界面里是项目目录），一个项目一份。
- 后续把清单里的写法补进 `核.py` 的对照表，就变成中文可写了。

### 2.5 把未定义写法补成中文

打开 `未定义.txt`，看到 `sum	内置函数` 这类记录，就在 `核.py` 的 `函数表` 里加一行：

```python
"核求和": "sum",
```

再运行一次，`核求和（…）` 就是中文了，清单里的这一条也会消失（下次运行时不再出现）。

方法、关键字参数同理：分别加到 `方法表`、`参数表`。

### 2.6 汉字变量名

和 Python 一样，汉字可以直接当变量名、函数名：

```
总分 = 92
名字们 = 核列表（）
核用 名字 遍历 名字们：
    核说（"你好，" + 名字）
```

## 四、实现说明

**转译而非重写解释器**：`.xht` 先被逐字符扫描成 Python 源码，再交给 Python 编译执行。

- **行号不变**：转译只做等长替换（全角→半角）、加固定前缀（`核"` → `f"`），
  从不增删换行。所以运行时报的「第 N 行」和 `.xht` 原文一一对应。
- **字符串优先**：扫描器先识别字符串（含三引号、转义、`r/b/u/f` 前缀），
  字符串内部不做任何关键字替换，全角标点也保留。
- **上下文判断**：`.方法` 只在点之后翻译；`核尾=` 只在参数位置翻译；
  赋值语句左边的名字视为用户自定义，不进未定义清单。
- **f 字符串递归**：`核"…{表达式}…"` 里花括号中的表达式会单独再转译一遍，
  所以 `{核长度(名字)}`、`{核最大(数字们)}` 都能用。
- **错误提示中文化**：语法错误同时给出「原文 / 转译 / 原因 / 提示」四行；
  运行错误给出异常名、`.xht` 里的行号和该行原文，常见异常附中文提示。

**图形界面**：`tkinter` 实现，无第三方依赖。代码高亮用正则一次性打标签；
运行程序走 `subprocess` + 独立线程读管道，所以运行中界面不卡，也能实时输入。

## 六、自测

```
python 测试/跑全部.py     核核 全量回归：18 项测试集（改动后必跑）
python 测试/自测.py       核核 内核自测：转译规则、运行结果、错误行号、未定义清单
python 测试/自测Qt.py     核核 Qt 界面功能自测：布局/新建/保存/高亮/运行/停止/查找替换/缩进/主题/设置
```

都是标准库 `unittest` 或纯断言，不依赖第三方包。

`跑全部.py` 跑完还会对一遍**源码树指纹**：测试里只要有人对当前文档按下保存、
而那个文档恰好是从例子目录打开的，就会把仓库里的示例文件写掉（真的发生过）。
指纹不一致会直接判失败并列出被改动的文件。

## 七、已知限制（第一版）

- 转译器是逐字符扫描的，不做完整语法树分析；极少数写法（如把关键字拼进
  字符串前缀位置）可能与预期不同。
- 未定义清单只识别**英文**写法；中文里没定义的新词按普通变量名处理。
- 图形界面只做单文件运行，没有断点调试、代码补全、工程级重构。
- `import` 能用，但标准库之外不提供任何第三方库封装（按需求「不引入库」）。
- 文件末尾没闭合的字符串会照原样交给 Python 报错（`引号没有配上对`），
  转译器**不再**替用户补上收尾引号。
