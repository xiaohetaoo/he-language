# 核语言 版本记录

每个版本都完整归档在 `版本/` 目录，可随时回看或对比。

版本号从 **0.0.1** 起，遵循 `主版本.次版本.修订号`：

- **主版本**：语言语法或运行方式有不兼容变化
- **次版本**：新增成体系的功能（如新的对照表大类、新的界面模块）
- **修订号**：修 bug、调样式、改文档

**每一段都不许到 10 —— 满了就往前一位进位**（用户 2026-10-28 明确要求）：

```
0.0.8 → 0.0.9 → 0.1.0 → 0.1.1 → … → 0.1.9 → 0.2.0 → … → 0.9.9 → 1.0.0
```

也就是说**没有 0.0.10 / 0.0.11 这种写法**。历史遗留的 0.0.10、0.0.11、
0.0.12、0.0.13 是按旧规则发的，tag 与 Release 都已存在，不改名；
按进位规则它们的等价写法是 0.1.0、0.1.1、0.1.2、0.1.3 ——
所以**下一个版本号从 `0.1.4` 起**。

## 发布流程

```
1. 改代码
2. 把 核.py 里的 版本 改成新版本号（记住：每一段到 10 要进位，见上）
3. python 测试/归档版本.py     核核 归档到 版本/vX.Y.Z/
   （同一版本号内又改了 bug，用 归档版本.py --覆盖）
4. 在下面的表里补一行，并写一段「## X.Y.Z 发布说明」（Release 正文取这一段；
   没有这一段时退回去取「## X.Y.Z 详细说明」）
5. python 测试/打包Qt.py        核核 重新出 exe（会自动跑自检）
6. git push origin main ；git push origin vX.Y.Z
7. python 测试/发布Release.py   核核 创建 Release 并上传 exe（需 GH_TOKEN）
```

> 0.0.6 起界面主推 Qt 版：打包用 `测试/打包Qt.py`（产物 `dist/核工坊Qt.exe`），
> 发布脚本会自动改名为 `HeLanguage-x.y.z-win64.exe`。
> **附件名必须是纯 ASCII** —— 中文名会被 GitHub 解析成 `default.exe`。
> 107MB 的 exe 必须流式上传：一次性 sendall 在慢链路上 900 秒也传不完。

> 发布 Release 需要 Personal Access Token（Contents 读写权限）。
> 只用 SSH 密钥只能 push 代码，不能上传 Release 附件。

查看已归档版本：

```
python 测试/归档版本.py --列表
```

界面里也可以看：**帮助 → 版本历史**（列出 `版本/` 下所有归档，
标出当前版本）。

## 0.0.13 发布说明

这一版把用户报的 **16 个问题**逐条实测复现后全部修掉，另加 3 个自查发现的问题。

### 高

- **自动配对在真实键盘上对 `( [ { "` 全部失效**（0.0.8 引入的回归）。
  这几个符号必须按住 Shift 才打得出来，而守卫写的是 `not 事件.modifiers()`，
  Shift 一来就短路，只输入单个字符、不补另一半。
- **「关闭其他标签」静默丢弃所有未保存的修改**。它先把 `已改` 抹成 False
  再强制关闭 —— 批量操作比单个关闭还危险。现在逐个弹保存确认，取消即中止。

### 中

- **「替换 / 全部替换」不遵守「区分大小写」**，查找和替换两套口径。
- **语法高亮**：字符串**内部**的关键字/内置名被后置规则覆盖成关键字色；
  三引号跨行不识别；全角引号 `「」『』“”` 不识别。现在字符串、注释、关键字
  共用内核的同一个扫描器（`核.扫描行`），优先级不再依赖规则顺序。
  同族问题一并修了：注释里的内容也被染色、ASCII 引号被全角 `」` 提前截断
  （`例子/08_异常处理.xht` 曾因此编译不过）。
- **`核 检查` / `核 转译` 对不存在的路径抛英文 traceback**，也没有拦目录。
  三个入口现在统一给中文提示。
- **`核 工坊` 打开的是冻结在 0.0.6 的 tkinter 旧版**，而文档写的就是这条命令。
  现在指向 Qt 版，旧版保留成 `核 工坊旧`。
- **每次 `Ctrl+S` 都在 GUI 线程同步跑 4 个 git 子进程**（实测 272ms，
  仓库一大就是秒级冻结）。挪到后台线程，并把连点产生的请求合并成一次。
- **字段里嵌套中文 f-string 转译错误**：`核说(核"外层{核"内层"}结束")`
  的产物编译不过（PEP 701 盲区，归一化阶段也有同一个盲区）。

### 低

未定义计数虚高、控制台把无换行输出拆成两行、连续运行时上一轮输出串台、
已打开的对话框不跟主题换、配置非原子写（半截 JSON 会让设置静默全丢）、
运行与 F9 的未定义清单互相覆盖、开发模式跑用户程序闪黑窗、
「运行中」状态点用 QSS `color` 改 QPixmap 所以视觉反馈实际不存在 —— 全部修复。

### 自查发现

- **`测试/冒烟Qt.py` 每跑一次都往源码树里写 `例子/01_你好.xht`**。
  它打开真例子，后面有个「保存」步骤写回当前文档路径。已改为用临时副本，
  并在回归里加了**源码树指纹闸**：跑测试期间仓库文件被动过就直接判失败。
- 中文引号左右改为**各自配对**（`“` 只由 `”` 收尾）—— 以前 `核说（“成绩里
  没有「数学」这一项”）` 里的 `」` 会被当成外层 `“` 的收尾符，字符串从中间断开。
- 文件末尾未闭合的字符串不再被悄悄补上引号，改为照原样交给 Python 报错，
  并给出中文提示。
- `版本控制` 面板双击重命名条目打不开（porcelain 的 `旧名 -> 新名` 原样存了）。
- 折叠重算加了缓存：8000 行文件从 18.7ms/键降到 7.1ms/键。

### 测试

全量回归 **15 项 → 18 项**，全部通过。新增 `测试/查高亮.py`（高亮优先级与
字符串/注释边界）、`测试/查命令行.py`（命令行中文提示）、`测试/查配置.py`（原子写）。

## 0.0.13 详细说明

**逐项验证用户报的 16 个问题，全部实测复现、修复、补测试**

这一版的每一条都先写了复现脚本确认现象，再改代码，再补回归用例。
下面按「现象 → 根因 → 修法」记，方便以后回看。

### P1 高

**1. 自动配对在真实键盘上对 `( [ { "` 全部失效（0.0.8 回归）**

- 现象：`编辑器.keyPressEvent` 里两处守卫都写 `not 事件.modifiers()`。
  但这四个符号在真实键盘上**必须按住 Shift**，Qt 给的事件于是必然带
  `ShiftModifier`，两个分支都被短路，只输入单个字符、不补另一半。
- 为什么测试没拦住：`测试/查配对.py` 一直用
  `QKeyEvent(KeyPress, 0, Qt.NoModifier, ch)` 这种「key 就是字符值、
  没有修饰」的假事件，天然绕过了这道检查 —— 是盲区，不是偶发。
- 实证：无修饰的 `(` 事件配对出 `()`；真实形态
  `QKeyEvent(KeyPress, Qt.Key_ParenLeft, Qt.ShiftModifier, "(")`
  只得到 `(`。`{`、`"` 同理。
- 修法：判断时**放行 Shift**，只让 Ctrl/Alt/Meta 让路。
  另外 `super().keyPressEvent` 那条「跳过已有右括号」的分支原本没有
  修饰检查，现在也加上，两边对称。
- **踩到的坑**：第一版写成 `事件.modifiers() & ~Qt.ShiftModifier`，
  结果 Ctrl+( 仍然会配对。原因是 PySide6 的 `Qt.KeyboardModifier`
  只声明了老的那几位（掩码 `0x1FFFFFF`），而
  `ControlModifier = 0x4000000` 在掩码之外，`~` 取不到它。
  改成整数位运算（`int(....value)`）才对。
- 测试补了「真实键盘形态」一整组，包括「只按第一个键看有没有配对」
  和「Ctrl/Alt 组合不许配对」。

**2. 「关闭其他标签」静默丢弃所有未保存的修改**

- 现象：`_关闭其他标签` 先把每个文档的 `已改` 置为 False，再
  `关闭文档(编, 强制=True)`。用户改了好几个文件后右键「关闭其他」，
  所有未保存的修改无提示直接丢失。
- 单个关闭走的是「要保存吗？是/否/取消」三选一，
  **批量操作反而比单个操作更危险**，这个不对称不像有意设计。
- 修法：遍历时逐个走现有的保存确认框，任一「取消」即中止。

### P2 中

**3. 「替换」「全部替换」不遵守「区分大小写」**

- 现象：`查找对话框` 调 `替换当前/全部替换` 时没传 `勾区分` 的状态，
  而 `编辑器.全部替换` 里的 `self.find(词)` 不带旗标。
  查找只定位精确匹配，一点「全部替换」却把大小写不同的也换掉 ——
  查找和替换口径不一致，且替换破坏性更大。
- 修法：两个方法都加 `区分大小写` 参数，一路传到底；
  `替换当前` 判断「选中项是否就是查找词」也按同一口径比较。

**4. 高亮：字符串内容被后置规则覆盖；三引号与全角引号不识别**

- 现象：规则按列表顺序 `finditer + setFormat`，字符串规则排第一，
  后染的关键字/内置/数字把字符串**内部**的内容盖上。
  实测 `核说("核若 核长度")` 里字符串中的「核若」被染成关键字色
  `#cf8e6d`、「核长度」染成内置色 `#d5b778`。
- 附带两个同类缺口：三引号跨行时第 2 行起无字符串染色；
  `「」‘’“”` 内核当字符串边界，高亮却不认。
- 修法：在 `核.py` 里新增 `扫描行(s, 起始引号=None)`，**一次左到右扫完**
  一行，同时给出「字符串区间、注释起点、跨行未闭合的三引号」。
  高亮器用它替换掉原来的三套独立判定：
  注释走 `注释起`，其余规则跳过落在字符串区间里的命中，
  最后再统一染一遍字符串（优先级不再依赖列表顺序）。
  跨行三引号用 `QSyntaxHighlighter.setCurrentBlockState` 记块状态
  （这是 Qt 为高亮器准备的接口；自定义块数据走 `QTextBlockUserData`，
  两者互不干扰）。全角引号进 `_字符串起点` 与新增的 `引号收尾` 表。
- 顺带修掉一个更严重的：`引号收尾` 第一版把 `”」』` 也算进 ASCII `"` 的
  收尾集，导致 `核说("成绩里没有「数学」这一项")` 直接编译不过
  （`例子/08_异常处理.xht` 就是这么挂的）。ASCII 引号只认 ASCII 引号。
- 同一个毛病在**注释**上也存在，一并修了：`核核 核说(1) 核若 123`
  里的「核说」「核若」「123」原本被染成内置色/关键字色/数字色
  （注释先染、后面的规则又盖上去），一条注释花花绿绿像代码。
  现在规则对「落在字符串里」和「落在注释里」的命中一律跳过，
  注释与字符串最后各染一遍。

**5. CLI 对不存在文件/目录路径抛英文 traceback**

- 现象：`核 检查 不存在.xht`、`核 转译 不存在.xht` 直接
  `FileNotFoundError` traceback；`核 运行 例子`（传目录）
  `PermissionError`。`运行` 有「找不到文件」的中文提示，
  但 `检查/转译` 没有，三个入口也都没拦目录。
- 修法：新增 `路径问题(路径)`，三个入口统一先过；
  `转译 -o` 写不出文件也给中文提示。

**6. `核 工坊` 打开的是 tkinter 旧版**

- 现象：`核工坊.cmd` → `核.py 工坊` → `import 核工坊`（tkinter 版，
  0.0.6 起冻结）。Qt 版没有任何命令行入口。
  而 README 和 说明.md 的快速开始都写着「双击 核工坊.cmd，或执行 核 工坊」——
  用户照文档走，进来的是没有代码折叠、版本控制面板、帮助菜单的旧界面，
  然后把旧界面的毛病当成新版的问题。
- 修法：`工坊` 分支改为 `import 核工坊Qt`；PySide6 缺失时**说清原因**
  并退回旧版（不是静默换）；旧版保留成 `核 工坊旧`。文档同步更正。

**7. 每次 `Ctrl+S` 都在 GUI 线程同步跑 4 个 git 子进程**

- 现象：`保存()` 末尾直接调 `刷新版本状态()` → `版本控制.状态()`，
  串行跑 `--is-inside-work-tree`、`rev-parse`、`status --porcelain`、
  `rev-list` 四个子进程，每个超时上限 6 秒。
  本仓库实测单次 272ms，全程占着 GUI 线程。
  启动时改 `QTimer.singleShot(0, ...)` 只是把它推迟到事件队列末尾，
  仍然是主线程同步跑，没解决卡顿。
- 修法：新增 `版本查询器`（QObject）+ `_版本任务`（QRunnable），
  放进 `QThreadPool` 里跑，结果用信号回填。
  同一时刻只允许一个查询在飞，飞行期间的请求合并成一次补跑 ——
  连点保存不会堆出一串并发子进程。退出前 `停()` 等它收尾。
- 测试补了「刷新立刻返回」「连点 30 次也几乎不耗时」「后台结果回填一致」。

**8. f-string 字段里嵌套中文 f-string 转译错误**

- 现象：`核说(核"外层{核"内层"}结束")` 的产物是
  `f"外层{核"内层"}结束"` —— 内层的 `核"` 没被转成 `f"`，
  编译报一句晦涩的 `f-string: expecting '=', or '!', or ':', or '}'`。
- 根因：外层字符串扫到字段内第一个引号就认为字符串结束了，
  后半段不再走字符串翻译。英文嵌套 `f{f"..."}` 凑巧能过
  （原文已是合法 PEP 701 源码，产物原样保留），中文嵌套必死。
- 修法：新增 `_找f串结束`，扫描 f-string 收尾时把 `{…}` 字段整段跳过
  （Python 3.12 起允许字段里复用外层同款引号）。
  同时修掉 `规范化源码` 里的同一盲区 —— 全角引号版本
  `核说（核“外层{核“内层”}结束”）` 就是在归一化阶段被字段内的 `”` 截断的。
  字段内容由 `处理f内容 → 转译(表达式)` 再单独处理一次，该归一化的照样归一化。

### 2. 代码折叠

以冒号结尾、且下一行缩进更深的行可以折。行号左侧显示 `▼`（展开）
或 `▶`（折起），点一下切换。

```
▼ 核定义 算总分(成绩单)：
▶ 核说("算完了")
```

几个要说明的设计点：

**折叠标记存在 `QTextBlockUserData` 上，不是 `userState`。**
第一版用了 `setUserState()`，结果是：新文档里每一块都「看起来已折叠」，
而且一跑高亮折叠就没了。原因是 **`userState` 被 QSyntaxHighlighter
内部占用** —— Qt 每次重新高亮都会把上一块的 userState 往下传播，
默认值还是 `-1`（所有位都是 1）。`QTextBlockUserData` 才是 Qt 给
「用户自己的块级数据」准备的位置，高亮器不碰它。

存在的意义是**跟着块走**：行号会随编辑漂移（上面插一行，下面所有折叠
就错位），而块级数据由 Qt 负责在插入/删除时搬运过去。

**光标不会停在被折起来的行上。** 万一落进去（查找定位、撤销、
`Ctrl+End`），那一块会自动展开。这是硬性安全要求 —— 绝不能在看不见的
地方改到代码。

**冒号被删掉就自动失效。** 折叠标记还挂着、但那一行已经不是块开头时，
标记会被清掉并把行放出来。

快捷键沿用 VS Code 的习惯：`Ctrl+Shift+[` 折叠、`Ctrl+Shift+]` 展开、
`Ctrl+Shift+9` 全部折叠、`Ctrl+Shift+0` 全部展开。

## 0.0.11 详细说明

**一次全量代码审查，修掉 11 个真 bug**

这一版没有新功能，全部是审查的结果。逐个说清楚「什么现象、为什么、怎么改的」。

### 1. 打引号凭空多出三个字符（最严重）

打 `核说("中文")` 得到的是 `核说("中文")"")`。

原因：自动配对的「右邻已有配对符号就跳过」逻辑只对右括号生效，
而引号**既是配对表的键又是值** —— 按 `"` 时先命中了自动配对分支、
插出一对 `""`，用户再按 `"` 收尾时又插一对。

改法：把「右邻已是配对的那一半」的检查提到自动配对**之前**，
对引号同样适用。现在打 `核说("中文")` 就是 `核说("中文")`。

### 2. 高亮和翻译对同一行给出两种解释

`核核紧贴`（「核核」后面紧贴文字）在翻译器里**不是**注释 ——
`词右界` 要求「核核」后面不能紧贴标识符字符。但语法高亮用的是
`核核[^\n]*` 无条件匹配，会把它染成注释色。

同一行，编辑器说「这是注释」，内核说「这是代码」。

改法：注释不再用正则匹配，改为逐位置扫描，直接调用 `核.词左界/词右界`
—— 和翻译器**共用同一套判定**。附带修掉：字符串里的 `核核`
（`核说('核核 在字符串里')`）以前会被染成注释色。

### 3. 「检查语法」的报错用户根本看不到

按 F9 有语法错误时，状态栏提示「语法有误，见运行窗口」，
但错误详情被写进了 `sys.stderr` —— GUI 里 stderr 没有去处，
运行窗口也从来没收到过这段输出。用户只看到一句没头没尾的话。

改法：把错误输出接进运行窗口的控制台，状态栏同步说明。

### 4. 按 F9 永远看不到未定义清单

`检查语法` 用的是 `未定义报告(None)`，而 `保存()` 遇到 `None` 路径会
直接返回 —— 清单根本没写盘。

改法：报告写到项目目录。

### 5. 设置里按「取消」，项目目录却改了

在设置 → 运行里换了项目文件夹，程序立刻换树并写盘。
但按「取消」只还原了主题、字号、行号、缩进线、高亮，
**项目目录没还原** —— 等于「取消」没取消干净。

改法：`取消()` 里一并还原项目目录与路径框文字。

### 6. 未定义清单写到了错的地方

`默认报告路径(源文件)` 收了「源文件」参数却完全没用，
永远写到进程当前目录。于是从别处运行 `核 运行 D:\项目\a.xht`，
清单掉到当前目录，而不是项目目录；而且 `核 报告 D:\项目\a.xht`
查的是源文件目录下的清单，和实际写出的位置对不上。

改法：清单写到**源文件所在目录**（真的一项目一份），
`核 报告` 与运行时用同一个算法，GUI 也优先查当前文档所在目录。

### 7. 每次开菜单都漏一批 QAction

`弹主菜单` 每次新建约 44 个 `QAction`，父对象是**主窗** ——
菜单关掉后它们不会被回收，全堆在主窗里。
实测开 15 次菜单，主窗里积了 660 个。

改法：QAction 的父对象改成**菜单**，菜单用完 `deleteLater()`。
实测开 15 次菜单后主窗里 QAction 数为 **0**。

### 8. 「切换注释」不认英文 `#` 注释

只认 `核核 `，英文 `#` 注释行永远被当成「没注释」，
在混排文件里行为不一致。取消注释时也只去 `核核 `，
`# hello` 会被去掉 `# ` 之外的字符。

改法：两种前缀都认；判定「是不是注释」也和翻译器一致
（`核核紧贴` 仍然不算注释）；取消时精确去掉对应前缀。

### 9. 缩进线开关要等下次重绘才生效

`应用设置` 直接改 `self._缩进线开`，没有像 `设缩进线()` 那样调
`viewport().update()`，勾选框切换后要等下一次重绘才看得出变化。

改法：走 `设缩进线()`。

### 10. 顺带修掉的

- 归档脚本漏了 Qt 版打包入口 `_启动Qt.py`
- 顶行里有一行重复的注释（`# 用大图让 Qt 自己平滑缩放。` 写了两遍）

  改用自造属性名 `窗态`。
- **圆角判定读到了旧状态**：`WindowStateChange` 事件里 `isMaximized()` 与
  `geometry()` 都可能还是旧值，且无边框窗口的 geometry 永远不等于
  availableGeometry（DWM 边框被裁掉）。改为立即设 DWM、延后一帧再设 QSS 属性。
- **测试会写坏用户真实配置**：跑一轮回归就把字号/制表宽覆盖掉。加 `核工坊_配置目录` 环境变量隔离

  `说核()` 读到的「小明」被按 GBK 解码成「灏忔槑」。根因有两层：
  ① 内核只有 `准备输出()` 没有 `准备输入()`；
  ② 打包入口直接调 `核.命令行()`，**绕过了 `主入口()`**，
  所以连 `准备输出()` 也没执行 —— `--版本` 的输出同样是 GBK 字节。
  现在补 `准备输入()`，入口改走 `核.主入口()`。

- **正文被行号栏遮挡**（这才是「每行吞字」的真正原因）：
  行号栏宽 58 的关键在于 `viewportMargins` 要等于它，但代码里用了
  `self.行号.isVisible()` 判断 —— 编辑器还没显示到屏幕上时 isVisible()
