# 核语言 版本记录

每个版本都完整归档在 `版本/` 目录，可随时回看或对比。

版本号从 **0.0.1** 起，遵循 `主版本.次版本.修订号`：

- **主版本**：语言语法或运行方式有不兼容变化
- **次版本**：新增成体系的功能（如新的对照表大类、新的界面模块）
- **修订号**：修 bug、调样式、改文档

## 发布流程

```
1. 改代码
2. 把 核.py 里的 版本 改成新版本号
3. python 测试/归档版本.py     核核 归档到 版本/vX.Y.Z/
4. 在下面的表里补一行
5. python 测试/打包Qt.py        核核 重新出 exe（会自动跑自检）
6. git push origin main ；git push origin vX.Y.Z
7. python 测试/发布Release.py   核核 创建 Release 并上传 exe（需 GH_TOKEN）
```

> 0.0.6 起界面主推 Qt 版：打包用 `测试/打包Qt.py`（产物 `dist/核工坊Qt.exe`），
> 发布脚本会自动改名为 `HeLanguage-x.y.z-win64.exe`。
> **附件名必须是纯 ASCII** —— 中文名会被 GitHub 解析成 `default.exe`。
> 107MB 的 exe 必须流式上传：一次性 sendall 在慢链路上 900 秒也传不完。

> 发布 Release 需要 Personal Access Token（Contents 读写权限）。
> 只用 SSH 密钥只能 push 代码，不能上传 Release 附件。

查看已归档版本：

```
python 测试/归档版本.py --列表
```

界面里也可以看：**帮助 → 版本历史**。

## 0.0.10 详细说明

**未保存的文档按运行，改为弹保存框**

用户截图报：按运行后状态栏只闪一句「请先保存再运行（Ctrl+S）」。

| 项目 | 原来 | 现在 |
| --- | --- | --- |
| 未命名文档按 F5 | 状态栏一句提示，什么都不发生 | 弹保存对话框，选好路径即存盘并运行 |
| 用户取消 | — | 状态栏「已取消运行」，不启动程序 |
| 后缀 | 用户不写就没有后缀 | 自动补 `.xht` |
| 默认目录 | 文件名裸值（停在进程当前目录） | 项目目录 + 建议文件名 |
| 运行前保存失败 | `self.保存(...)` 返回值被丢弃，静默失败 → 跑的是磁盘旧版本 | 保存失败则转「另存为」，仍失败就取消运行 |

**顺带修掉的缺陷**

- **「检查语法」在未保存文档上被拦**：它编译的是编辑区文本（`取文本()`），根本不需要文件已保存。那句「先保存文件再检查语法」是多余限制，用户在未命名标签里按 F9 会被挡住。现在未保存也能检查，路径只用于错误信息前缀。

**新增回归断言 5 项**：未命名触发保存框（而非只提示）、自动补后缀、文件真的落盘、未保存也能检查语法（正确/错误两种情况）。

另修一处测试脆弱点：`逐项验证` 里原本断言 `_复制路径()` 返回 `None`，而 Windows 上剪贴板可能被其他程序短暂占用（实测偶发 `OleSetClipboard: OpenClipboard 失败`），会造成误报。改为只验证「调用不抛异常」。

## 0.0.9 详细说明

**字号设置：下拉框 → 滑动条，范围 9–22 → 8–40**

用户报「可改字号范围太小了，并且要改成滑动条形式」。

| 项目 | 原来 | 现在 |
| --- | --- | --- |
| 控件 | `QComboBox` 枚举 9–22 | `QSlider` 8–40，带刻度 |
| 范围定义 | 主窗写 `min(9)/max(22)`、设置窗写 `range(9,23)`、自检另写一份 | `主题.字号最小/最大/步长` 一处定义，`主题.夹字号()` 统一夹取 |
| 拖动反馈 | 选完才看到变化 | 拖动中 30ms 去抖实时预览，数值标签即时更新 |
| 松手 | — | `sliderReleased` 立刻落实最后一个值，不等去抖 |

**顺带修掉的缺陷**

- **设置窗口文字在浅色主题下几乎不可见**：标题「外观」、「配色 / 编辑器字号 / 界面元素」这些分组标题，颜色是用 `setStyleSheet("color:<当前主题文本色>")` 行内写死的，换主题时不会更新 —— 从深色切到浅色后仍是深色主题的浅灰 `#DFE1E5`，在浅底 `#F7F8FA` 上对比度只有 1.05。改为 `objectName` + QSS 统一管理。
- **滑块渲染成方块 / 竖条 / 胶囊**：`QSlider::handle` 的 `width/height` 是内容区尺寸，`margin` 会撑高。只写 `width` 会被拉成竖条；写负 `margin` 会变胶囊；同时写 `width/height + margin` 会丢 `border-radius` 变成方块。最终方案：groove 做到 16px 高留出正方形空间，用竖直渐变让可见轨道只占中间 4px，handle 内容 8px + 边框 3px = 14px 见方、半径 7 → 正圆。

**新增回归断言 7 项**：滑动条范围 == 主题常量、超范围值被夹住、范围两端行高真的不同、拖滑动条当场生效、数值标签同步、取消后滑块也回原值。界面可见性审查从 186 项增至 188 项，并确认新加的文字角色（`pageTitle`/`groupTitle`/`hintText`/`sliderValue`）在深浅两套主题下都被实际量到（16.04 / 10.33，阈值 4.5）。

## 0.0.8 详细说明

**用户报的三处问题，逐一定位到根因**

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 全屏没占满 | 窗口矩形实测精确等于屏幕可用区（误差 0 像素），缺的是四个角：#rootFrame 的 `border-radius: 12px` 在最大化时仍生效，加上 DWM 圆角偏好，四角被切掉露出桌面 | 按窗口状态切 QSS 属性让圆角归零，同时把 DWM 圆角偏好设为 `DONOTROUND`。真实桌面截屏验证：还原态四角是桌面色 `#1b1b1c`，最大化后四角全是窗口色 `#2b2d30` |
| 行标是歪的 | `blockBoundingGeometry` 给的是内容坐标，加 `contentOffset()` 后是**视口坐标**，代码却又减了一次行号栏自己的 `y()`（恰好 6px），整体上移 6px | 改成补「视口 y − 行号栏 y」之差；行高用块的实测高度，垂直居中交给 AlignVCenter |
| 设置不能马上生效 | ①「显示行号」只改主窗属性，从未作用到编辑器；②「自动语法高亮」的勾选框**根本没连信号**；③「应用」不写盘；④取消只还原主题和字号 | 每项都走 setter 直达编辑器，「应用」写盘，「取消」逐项还原 |
| 调字号没有变化 | QSS 里 `QWidget { font-size: 13px }` 的优先级**高于 `setFont()`**，编辑器设的 `QFont` 点数被完全覆盖 —— `QFont.pointSize()` 恒为 -1、`fontMetrics` 高度恒为 16。更隐蔽的是：`__字号__` 占位符虽然算出来传进去了，**模板里一次都没用** | 模板里给 `QPlainTextEdit`/`#gutter` 写 `font-size: __字号__px`，改字号走 `_套样式()` 重建整份样式表。实测行高 10→14→19→24 随字号变化 |

**同时修掉的其它缺陷**

- **缩进参考线压正文**：1 级缩进的行也在 x=16 画线，正文从 x=19 起，只差 3px，看起来像行首多一个竖线字符。改为只画外层层级（与 PyCharm / VS Code 一致）
- **三个窗口按钮样式从未生效**：QSS 写 `#winBtn`/`#closeBtn`，代码实际的 objectName 是 `窗口钮`/`关闭钮`，一条都没匹配上 —— 没有悬停反馈、关闭钮不变红
- **对话框默认按钮被抢**：Qt 会在显示时把「默认按钮」转给焦点链里第一个 autoDefault 按钮，实测「更改…」变成蓝色主按钮，按回车去弹文件选择框。改为 `autoDefault=False` + 自定义 `primary` 属性控制样式
- **无边框窗口不能拖边缩放**：`FramelessWindowHint` 下系统不做边缘缩放，也没有缩放光标。补上 `startSystemResize` 与四边/四角光标
- **行号栏宽度不随字号自适应**：写死 `16 + 位数*9`，9 这个系数只在小字号下够用；字号 20/22 时三位数字要 35~39px 而宽度仍 43，减掉右边距只剩 33，数字被裁掉一截。改为按字体实测字宽算
- **下拉框右端一块亮斑**：Fusion 样式默认的箭头区底色 + 分隔线。改为自绘三角箭头（QSS 不支持 CSS 边框拼三角形，写了会渲染成实心方块）
- **对照表漏了「遍历」**：`in` 有两种中文写法（核在 / 遍历），反查字典只保留最后一个。改为英文→写法列表
- **对照表第六节表格列数不符**：表头 2 列、数据 3 列
- **QSS 自定义属性名撞上内建属性**：圆角规则写的是 `#rootFrame[maximized="true"]`，
  而 `maximized` 是 QWidget 的内建只读属性 —— `setProperty` 被静默吞掉，
  读回来永远是 False、`dynamicPropertyNames` 里也没有，规则**从未匹配过**。
  改用自造属性名 `窗态`。
- **圆角判定读到了旧状态**：`WindowStateChange` 事件里 `isMaximized()` 与
  `geometry()` 都可能还是旧值，且无边框窗口的 geometry 永远不等于
  availableGeometry（DWM 边框被裁掉）。改为立即设 DWM、延后一帧再设 QSS 属性。
- **测试会写坏用户真实配置**：跑一轮回归就把字号/制表宽覆盖掉。加 `核工坊_配置目录` 环境变量隔离
- **打包 exe 里中文输入变乱码**：exe 的 `sys.stdin.encoding` 是 **gbk**（跟随系统代码页），
  `说核()` 读到的「小明」被按 GBK 解码成「灏忔槑」。根因有两层：
  ① 内核只有 `准备输出()` 没有 `准备输入()`；
  ② 打包入口直接调 `核.命令行()`，**绕过了 `主入口()`**，
  所以连 `准备输出()` 也没执行 —— `--版本` 的输出同样是 GBK 字节。
  现在补 `准备输入()`，入口改走 `核.主入口()`。

**新增回归断言 19 项**，锁住上述每一条，防止再犯。

### 第二轮审查修复（用户报「每行吞字 / 暗色看不清 / 设置入口冗余 / 图标太像」）

修掉的真 bug：

- **输入吞字**：编辑器 `_文本变化` 里同步调用 `更新状态栏()` 和 `_刷新标题()`。
  这两个都会改状态栏文字和窗口标题，进而触发重排重绘并**重入事件循环**；
  连续快速输入（尤其配合输入法）时后续按键会丢，用户看到的就是「吞字」。
  现改为去抖：文本与光标变化都攒进一个 30ms 的单次定时器，
  无论触发多少次只刷一次界面。
- **输入法标点打不出来**：自动配对会抢走 `'` `"` 的按键。
  中文输入法正是用这两个键触发中文标点，被 `return` 掉之后输入法收不到，
  表现为「标点被吞」。现输入法候选窗开着时自动配对一律让路。
- **设置窗口配色与主窗不一致**（用户截图里主窗浅色、设置窗深色，
  右侧标题深色叠在深色背景上几乎看不见）：设置窗口的 QSS 改为与
  主窗口同一个主题字典来源，不再可能取到另一套色。
- **暗色主题偏暗的四处颜色**：次要文本 `#9DA0A8→#B2B6BE`、
  行号字 `#7F848E→#9AA0AB`、注释 `#7A7E85→#9197A0`。
  现在深浅两套主题的正文/次要/行号/注释对比度全部 ≥ 4.5（WCAG AA）。
- **设置入口冗余**：顶行齿轮与左竖条齿轮重复。现只保留左竖条底部一个
  （与 PyCharm 一致），顶行去掉齿轮。
- **功能图标没有区分度**：原先用 `▤ ☰ ▶ ⚙` 符号，全是细线条，
  缩到 18px 后分不清。现改为 `画图标()` 自绘矢量图形并各配一色：
  文件夹（蓝）/ 列表（紫）/ 三角（绿）/ 滑块（灰）/ 状态点。

顺带：顶行运行按钮也改用自绘三角，与竖条图标风格统一。

## 0.0.4 详细说明

**字符串引号修复（审查发现）**

- 字符串内容里的 `「」` `『』` 曾被悄悄改写成 `"`，与「字符串内容保持原样」
  的承诺相违。原因是收尾判断用了 NFKC 归一后的字符，而 `「` 归一后正是 `"`，
  于是文内引用符号被当成结束引号。现改为只看原字符是否与起始引号配对。

**异常类型中文化**

- 新增 `异常表`：`除零错误`→`ZeroDivisionError`、`值错误`→`ValueError`
  `下标错误`→`IndexError`、`键错误`→`KeyError`、`类型错误`→`TypeError` 等 22 条
- 仅在 `核异常` / `核抛出` 之后生效，别处写同名变量不受影响
- `核异常 值错误 核作为 错误：` 里的 `错误` 仍按变量名处理，不会被替换
- 对照表新增「六、异常类型」一节

**中文模块导入**

- `核导入 工具` 现在能加载同目录的 `工具.xht`
- 支持 `核从 工具 核导入 甲`、`核导入 工具 核作为 工`
- 通过 meta path finder 实现，只认 `.xht`，不影响任何正常导入
- 找不到模块时的提示改为「.xht 模块要和主脚本放在同一目录」

**新增 3 个示例**

- `06_集合与文本.xht`：集合四则运算、包含判断、文本判断、对齐填充、
  切分合并、进制转换、编号遍历
- `07_类与对象.xht`：类定义、构造、继承、`核父类()`、类型判断、计数器
- `08_异常处理.xht`：分类捕获、`核作为` 绑定、`核最终`、主动 `核抛出`、
  `核否则` 分支

**关于页**

- 新增「查看最新版本与下载」链接，点击直接打开 GitHub 发布页

**测试**

- 内核 25 项（含 8 个示例全部跑通）、界面 98 项、对照表自检全部通过

## 0.0.2 详细说明

**界面**

- 顶部去掉重复标题栏：原先 Windows 原生标题栏和自绘标题栏各显示一次
  「核工坊 v…」，现在标题只由原生标题栏承担，自绘条只留品牌图标、

**健壮性**

- 关闭文档后仍有高亮定时回调打在已销毁控件上，抛 TclError；现关闭时

- 拖放模块的窗口过程引用、回调列表、已启用集合从不清理，窗口反复开关
  会持续累积；现新增 `释放拖放` 并在销毁时调用

**工具**

- 归档脚本支持 `--覆盖`（会先把旧版备份到 `_旧_vX.Y.Z`），不再要求手动删目录

## 0.0.7 修复明细

### 界面可见性（用户报「暗色主题下字看不清」「功能图标太像了」）

新增 `测试/审查可见性.py`：不靠看配色表，真的把控件渲染出来、取像素、按
WCAG 算对比度。色表看着没问题、实际画不出来，只有渲染时才看得出来。

- **12 处 QSS 声明整条失效**：`主题.py` 的模板里混用了两种占位符写法，
  写成 `{中文名}` 的那 12 条（按钮悬停、输入框、下拉框、勾选框、弹出菜单等）
  在生成样式时原样留在了 CSS 里，Qt 解析不了就整条丢掉。
  现象是这些控件一直用默认配色，换个主题也不变
- 生成样式补上兜底：占位符没替换干净的 `声明：值;` 直接剔除，不再带着
  `{...}` 交给 Qt（附一个断言，防止以后又混用）
- **顶行「运行」按钮看不见**：图标颜色硬编码成 `#1E1F22`，正好等于深色底，
  对比度 1.13 —— 等于没有。改成读主题的 `图标运行` 键
- **左上角品牌标记看不见**：用的是 `素材/核图标_32.png`，那张图 97% 是透明
  像素（细轨道线），缩到 20px 后几乎什么都没画上。改成矢量画原子，随主题换色
- **错误提示色对比度不足**：深色下 `#F75464` 在控制台底上偏暗，改 `#FF6B7A`
- **浅色行号字偏淡**：`#6E747D` → `#676D76`
- 竖条图标重新设计：原来全是细线条符号（▤ ☰ ▶ ⚙），缩到 18px 彼此分不清。
  改成实心几何形状 + 各自独立颜色：文件夹（蓝）/ 列表（紫）/ 终端（绿）/ 滑块（灰）
- 竖条「运行」原来也用播放三角，和顶行「运行」按钮撞脸 —— 一个只是开面板、
  一个真的执行程序，用户分不出。改成终端窗口造型

### 回归测试

### 第二轮补修（用户复查后报「每行还是吞字」「标志和核工坊字样别换」）

- **正文被行号栏遮挡**（这才是「每行吞字」的真正原因）：
  行号栏宽 58 的关键在于 `viewportMargins` 要等于它，但代码里用了
  `self.行号.isVisible()` 判断 —— 编辑器还没显示到屏幕上时 isVisible()
  是 False，左边距算成 0，正文就贴着最左边画、压到了行号下面，
  看起来就像每行开头少了一两个字。
  改成按自有的 `_行号隐藏` 标记判断，与「显示行号」开关同步。
- **行号栏宽度自适应**：原来固定 58px，行数上到三位数后数字会顶到边缘。
  现在按「最大行号位数」算宽度（至少 3 位），并同步更新 viewportMargins。
- **行号与正文垂直错位**：`blockBoundingGeometry` 的 y 是相对视口的，
  而行号区自身有 padding-top 偏移，没扣掉这个偏移会让行号整体偏下，
  第 2 行起正文就压进行号区里。现减去 `self.y()`。
- **自动缩进被叠加**：实测 QPlainTextEdit 原生回车**不**继承缩进
  （新行是空的），所以必须自己补完整缩进量；此前测试里既写了缩进
  又让程序补一次，导致 4→8→12 叠加，看起来像「每行多吞了空格」。
- **输入法组字状态改为自己记账**：`QGuiApplication.inputMethod().isVisible()`
  在 Windows 上实测恒为 False，「组字中要放行」那道守卫从未生效过。
  改为在 `inputMethodEvent` 里按 preedit 是否为空维护 `_组字中`，
  组字期间按引号不再自动配对，也不刷窗口标题
  （Windows 上 setWindowTitle 会取消 IME 组字，正在打的拼音会丢）。
- **顶栏恢复工作室标志 + 「核工坊」字样**（用户明确要求保留）：
  标志改用最大的 `素材/核图标.png`（530x470，18% 不透明）让 Qt 平滑缩放。
  绝不能用 `核图标_32.png` —— 实测它只有 3% 不透明像素、`_16.png` 是 0%，
  预缩阶段就把原子轨道抹平了，贴上去几乎空白。
- 新增 `测试/截图Qt.py`：一键重拍 README 用的四张截图。
- 回归测试补两条：正文首字必须落在行号栏右侧、冒号回车缩进等于制表宽。
